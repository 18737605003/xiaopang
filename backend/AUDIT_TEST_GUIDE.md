# 代码审计功能测试指南

## 测试前准备

### 1. 配置 API Key
1. 登录系统（admin/admin123）
2. 进入"系统设置"页面
3. 配置 Fireworks AI API Key
4. 保存配置

### 2. 准备测试仓库
可以使用以下公开仓库进行测试：

**小型仓库（推荐）**：
- https://github.com/expressjs/express
- https://github.com/koajs/koa
- https://github.com/fastify/fastify

**中型仓库**：
- https://github.com/nodejs/node
- https://github.com/microsoft/TypeScript

## 测试步骤

### 1. 提交审计任务

1. 进入"代码审计"页面
2. 输入 Git 仓库 URL（例如：`https://github.com/expressjs/express`）
3. 等待系统自动获取分支列表
4. 选择分支（通常是 `main` 或 `master`）
5. 点击"开始审计"

### 2. 观察进度

提交后会弹出进度对话框，显示：
- 进度条（0-100%）
- 当前状态（克隆中、分析中、已完成）
- 详细消息（正在分析哪个文件）
- **实时问题列表**（最近发现的 10 个问题）

进度阶段：
1. **10%** - 克隆仓库
2. **30%** - 分析代码结构
3. **35%** - 安全扫描（正则规则）
4. **40%** - AI 识别核心文件
5. **50-90%** - 深度分析核心文件（单线程）
6. **85%** - AI 生成总结报告
7. **95%** - 生成报告
8. **100%** - 完成

### 3. 查看报告

审计完成后会自动打开报告，包含三个标签页：

#### 概览
- 总问题数量
- 按严重程度分类（严重、高危、中危、低危）
- 代码统计（文件数、代码行数、语言分布）

#### 问题列表
每个问题包含：
- 严重程度标签（红色=严重，橙色=高危，黄色=中危，绿色=低危）
- 问题类型（memory_leak、logic_error、security 等）
- 文件位置和行号
- 问题描述
- 代码片段
- 修复建议
- CWE 编号（如果适用）

#### AI 洞察
AI 生成的整体评估，包括：
- 整体安全评估
- 主要风险点
- 优先修复建议
- 最佳实践建议

## 预期结果

### 规则扫描（快速）
应该能检测到：
- SQL 注入风险
- 硬编码密钥
- 不安全的 eval 使用
- XSS 漏洞
- 命令注入
- 弱随机数生成
- 弱加密算法

### 深度分析（AI）
应该能检测到：
- 内存泄漏（资源未释放）
- 逻辑错误（边界条件、空指针）
- 资源竞争（多线程问题）
- 缓冲区溢出（C/C++ 代码）
- 安全漏洞（更复杂的场景）

## 常见问题

### Q1: 进度卡在某个阶段不动
**原因**：
- API Key 未配置或无效
- API 限流（429 错误）
- 网络问题

**解决**：
1. 检查系统设置中的 API Key
2. 查看后端控制台日志
3. 等待几分钟后重试

### Q2: 没有发现任何问题
**原因**：
- 代码质量很好
- AI 未识别到核心文件
- 置信度阈值过高

**解决**：
1. 查看"AI 洞察"标签，看 AI 的整体评估
2. 检查后端日志，看识别了哪些核心文件
3. 尝试其他仓库

### Q3: 发现的问题太多
**原因**：
- 代码确实存在很多问题
- 误报（置信度较低的问题）

**解决**：
1. 优先关注"严重"和"高危"问题
2. 查看问题的 confidence 值（在数据库中）
3. 可以调整 `analyzeCodeChunk()` 中的置信度阈值（默认 0.7）

### Q4: 审计失败
**原因**：
- Git 仓库无法访问
- 分支不存在
- 磁盘空间不足
- API 错误

**解决**：
1. 检查仓库 URL 是否正确
2. 检查分支名称是否正确
3. 查看后端日志获取详细错误信息
4. 检查 `temp/` 目录是否有足够空间

## 调试技巧

### 查看后端日志
```bash
cd backend
npm run dev
```

关键日志：
- `📥 克隆仓库: ...` - 克隆开始
- `✅ 克隆完成: ...` - 克隆成功
- `📁 识别到 X 个核心代码文件` - AI 识别结果
- `🔍 分析文件 [X/Y]: ...` - 正在分析的文件
- `⚠️  [severity] type at line X` - 发现问题
- `✅ 深度分析完成: 总共发现 X 个问题` - 分析完成

### 查看数据库
```bash
cd backend
npx prisma studio
```

查看表：
- `AuditTask` - 审计任务
- `AuditReport` - 审计报告
- `issues` 字段 - JSON 格式的问题列表

### 手动清理临时文件
```bash
cd backend/temp
# 删除旧的审计目录
rm -rf audit-*
```
